# Handover: 2026-10-05

## Current status

The LunchApp pilot now supports employees and external account holders through ordering, kitchen operations, reporting, and external financial follow-up.

The main flows are operational:

```text
Card login
→ Employee or external session
→ Meal/salad order
→ Kitchen summary
→ Payroll or external reporting
→ External account balance/ledger where applicable
```

## Major deployed capabilities

### Employees

- Personal meal and salad ordering
- Guest ordering
- Kitchen visibility
- Cancellations
- Manual late lunch additions
- Payroll lunch report and CSV

### External accounts

- Card login
- Meal and salad ordering
- No guest ordering
- Kitchen visibility using cardholder name
- Separate external lunch report
- External and invoice references in CSV
- €11.35 lunch valuation from 2026-09-01
- Prepaid, postpaid, and invoice balance integration
- Lunch entries in external account ledger
- Balance visibility on kiosk card administration tiles

## Operational cautions

- Financial balance SQL is now dependent on `vwExternalLunchChargeEntries` and `ExternalLunchPrices`.
- Do not delete historical price rows.
- Do not insert derived lunch charges into `ExternalAccountLedger`; that would double-count them.
- When debugging HTTP 500 responses, use Azure Function Log Stream or Application Insights because response bodies may be empty.
- Keep complete replacement files as the authoritative deployed versions. Avoid manual snippets that create local/deployed divergence.
