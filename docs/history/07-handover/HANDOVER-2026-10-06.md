## Operational cautions

- Run `npm install` after replacing `package.json`; otherwise Functions fails with `Cannot find module '@azure/storage-blob'`.
- The Blob container is private by design. Do not change anonymous access merely to simplify frontend image loading.
- Do not delete rows from `ImageAssets` manually. Use the API so Blob content is also removed.
- Do not delete an image used by a product. The UI disables this and the API enforces it.
- Uploading from the Product Library occurs when `Use image` is clicked, not when the product is saved.
- Keep `ImageStorageConnection` secret and in Function App settings only.
- Keep complete replacement files as the authoritative deployed versions.

## Architecture decisions

- Product images are implemented now; meals and salads remain future consumers.
- The image table is generic and reusable.
- Images are normalized to 800 x 800 JPEG in the browser.
- GUID Blob names avoid collisions.
- SQL stores friendly metadata and Blob path, not a fixed storage URL.
- Product API generates the usable content URL.
- The kiosk currently merges current product data with layout data client-side.
