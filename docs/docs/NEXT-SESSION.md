# Next session

## Start with these tasks, in this order

### 1. Guest lunch ordering

Goal: make employee guest lunches operationally clear and correctly reportable.

Review:

- Guest-order API ownership
- Host employee number and name snapshots
- Guest company/name/comment fields
- Date and meal selection rules
- Cancellation/editing behavior
- Kitchen summary visibility
- Weekly CSV output
- Duplicate-submission protection

External accounts must not be allowed to order guest lunches.

### 2. Product image library

Build the proper version, not a temporary URL-pasting workflow.

Recommended design:

- Azure Blob Storage container for product images
- Managed Identity for the Function App
- Short-lived, write-only upload SAS generated by an authenticated API
- Browser upload directly to Blob Storage
- Client-side resize to a consistent WebP image
- Unique blob names to avoid cache problems
- Save the final public/read URL in `dbo.KioskProducts.ImageUrl`
- Upload, preview, replace and remove controls in Product Library
- Delete the previous blob only after the product update succeeds

### 3. Microsoft Entra ID access

Protect administration and financial reporting before production.

Suggested authorization roles:

```text
LunchApp-Users
LunchApp-Kitchen
LunchApp-CafeAdmins
LunchApp-Finance
LunchApp-SystemAdmins
```

Assign the roles to Entra security groups rather than individual users.

### 4. External lunch ordering

Only after guest-order ownership is understood.

Required model:

- `OwnerType`
- `EmployeeNo` or `ExternalAccountID`
- `CardID`
- Display-name and company snapshots
- Explicit rule preventing external guest lunches
- Reporting and invoicing inclusion

### 5. Scheduled reports

Deliberately postponed.

When resumed, manual and scheduled exports must call the same report service. Validate totals first, then add weekly/monthly Timer Trigger jobs and controlled delivery to SharePoint or another finance location.
